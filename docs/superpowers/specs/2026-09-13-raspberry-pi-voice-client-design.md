# Перенос голосового клиента human4ai на Raspberry Pi

## Цель

Убрать зависимость озвучки Яндекс-Станций от Windows-ПК и перенести домашний
узел human4ai на Raspberry Pi `PaulIslavaTV` (`192.168.1.123`). После миграции
сервер продолжает отправлять `voice.say` через существующий исходящий WSS-мост,
а Pi обнаруживает станции и выполняет glagol-команды внутри домашней LAN.

## Архитектура

Серверный `/api/bridge`, протокол ACK/response и приоритет bridge-first не
меняются. На Pi запускается тот же `dist/voice/client.js`, что сейчас работает
как NSSM-служба на Windows. Клиент устанавливает исходящее WSS-соединение к
`human4ai.paulislava.space`, поэтому входящий порт, frp и новый reverse tunnel
для озвучки не нужны.

Runtime располагается в `~/.local/share/human4ai-client`, конфигурация — в
`.env` с правами `0600`, автозапуск — пользовательская systemd-служба
`human4ai-client.service`. У пользователя `paulislava` уже включён linger,
поэтому служба работает без открытой SSH-сессии.

## Установка и конфигурация

На Pi устанавливается Node.js 20 из Raspbian. Локальная сборка TypeScript
копируется на Pi вместе с независимым mDNS-скриптом. Runtime получает только
нужные JS-зависимости: `axios`, `dotenv` и `ws`; нативная SQLite-зависимость
серверной части ему не нужна.

Перед запуском `scripts/find-stations.mjs` формирует статический
`VOICE_STATIONS` по mDNS. Человеческие подписи и default берутся из действующей
прод-конфигурации: `VOICE_STATION_NAMES` и device id алиаса `кабинет` в
`VOICE_STATION`.
Bridge-токен переносится напрямую из действующей серверной конфигурации в
защищённый `.env` Pi и не выводится в терминал или журналы.

## Переключение

1. Запустить клиент на Pi и дождаться регистрации станций на сервере.
2. Проверить `/api/voice/stations`, default-вызов (`кабинет`) и явный вызов
   `миди`.
3. Отключить на Windows службы `human4ai-client` и `lan-proxy`, сохранив их
   конфигурации для быстрого отката.
4. Повторить проверку после отключения Windows и убедиться, что ответ сервера
   содержит `via pi`.

Старый `VOICE_PC_PROXY` остаётся неиспользуемым legacy-параметром до отдельной
чистки серверных secrets; рабочая озвучка от него не зависит.

## Ошибки и восстановление

Systemd перезапускает клиент после сетевого сбоя. WSS-клиент переподключается с
экспоненциальной задержкой. Если Pi не регистрируется, Windows-служба снова
включается и запускается; сервер автоматически принимает вернувшееся
соединение. Windows-службы не удаляются в рамках миграции.

## Проверка

- `npm test -- --runInBand`
- `npm run build`
- mDNS discovery на Pi видит ожидаемые станции
- systemd-служба активна после выхода из SSH
- `/api/voice/stations` показывает станции Pi
- default-вызов возвращает `кабинет via pi`
- явный вызов возвращает `миди via pi`
- обе проверки остаются успешными после остановки Windows-служб
