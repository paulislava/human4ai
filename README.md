# human4captcha

Общая служба разгадывания капчи для любых процессов. Клиент шлёт картинку и
получает строку — он ничего не знает про модели и Telegram.

```
POST /api/captcha/solve  ─┐
                          ├─→ GigaChat-3-Ultra ─→ Claude Opus ─→ Павел в Telegram ─→ тайм-аут
             { answer } ←─┘
```

## Каскад

| # | Ступень | Что делает |
|---|---|---|
| 1 | `gigachat` | GigaChat-3-Ultra через `gpt2giga-proxy` — самая дешёвая попытка |
| 2 | `claude` | Claude Opus (vision) — дороже, но заметно лучше на искажённом тексте |
| 3 | `human` | Фото капчи в Telegram с `ForceReply`; ответ приходит реплаем |
| 4 | — | Тайм-аут: `answer: null`, клиент решает сам, что делать |

Порядок задаётся массивом в `config.ts`. Клиент может ограничить каскад —
`"solvers": ["human"]` спросит сразу человека.

Недоступные ступени (нет ключа, не настроен бот) выпадают из каскада
автоматически: `GET /api/health` показывает, что реально работает.

## Вопросы человеку

Тот же бот умеет спрашивать Павла о чём угодно, не только про капчу.

```
POST /api/ask/solve     → синхронно: ждём ответ и отдаём его
POST /api/ask           → асинхронно: { id }
GET  /api/ask/:id       → { status, answer? }
POST /api/ask/:id/retry → значение не подошло, спросить заново
POST /api/ask/:id/confirm → значение подошло (ставит 👍)
```

Тело: `{ question, kind?, context?, link?, options?, timeout_ms? }`.

| `kind` | Заголовок | Поведение |
|---|---|---|
| `text` (по умолчанию) | ❓ Вопрос | ответ читается сколько нужно |
| `secret` | 🔒 Нужен секрет | **отдаётся один раз** и стирается из базы |
| `code` | 🔑 Нужен код | то же, что `secret` |

- **`options`** превращают вопрос в **опрос Telegram** — ответ одним тапом,
  выбор приходит обновлением `poll_answer`. Секрет опросом не спрашивается: его
  набирают руками.
- **`link`** уходит в текст вопроса — так отправляется ссылка на вход, когда
  нужно, чтобы Павел где-то авторизовался и вернул код.
- Ответ на секрет **не попадает в логи** — ни значение, ни его длина.
- Реакции те же: 👀 ответ забрали, 👍 подошёл (`confirm`), 👎 нет (`retry`).

## API

```
POST /api/captcha/solve      синхронно: ждёт до timeout_ms → { answer }
POST /api/captcha            асинхронно → { id }
GET  /api/captcha/:id        → { status: pending|solved|timeout|failed, answer }
POST /api/captcha/:id/reject ответ не подошёл → следующая ступень
GET  /api/stats              точность решателей по логу попыток
GET  /api/health             живость + список доступных ступеней
```

Тело: `{ image: base64, hint?, context?, solvers?, timeout_ms? }`.
Авторизация — заголовок `X-Token` (токены клиентов в `CLIENT_TOKENS`, имя
клиента видно в логах и статистике).

### Зачем нужен `reject`

Капчу «решённой» делает не модель, а сайт, который принял ответ. Клиент,
получив отказ сайта, дёргает `reject` и получает следующую ступень — вместо
того чтобы начинать каскад сначала и снова платить за уже провалившуюся модель.

## Где работает

Служба живёт **на сервере**: `https://captcha.paulislava.space/api`, контейнер на
порту 4020, деплой из GitHub Actions по push в `main` (образ в GHCR, health-check
и откат — по образцу PaulIsMapa). База задач в томе `human4captcha-data`.

Клиенты (скрапер на ПК, что угодно ещё) ходят на внешний адрес с `X-Token`.

> Локально её держать не надо: Telegram отдаёт обновления **одному**
> потребителю, и вторая копия с тем же токеном воровала бы ответы у серверной.
> На Mac она к тому же не встаёт под launchd — агент зависает на чтении из
> `~/Desktop`, это защита macOS (TCC).

## Запуск локально (для разработки)

```bash
npm ci
cp .env.example .env   # заполнить ключи
npm run start:dev      # http://localhost:3200
npm test               # каскад, reject, аудит, переживание рестарта
```

Перед запуском останови серверную копию или подставь токен другого бота —
иначе поллеры будут воевать за обновления.

## Ступени на сервере

| Ступень | Состояние | Как ходит |
|---|---|---|
| `gigachat` | работает | контейнер `gpt2giga` в docker-сети `h4c`, модель `GigaChat-2-Max` |
| `claude` | работает | `claude` CLI в образе, авторизация токеном `CLAUDE_CODE_OAUTH_TOKEN` |
| `human` | работает | бот `@PaulIsCaptchaBot` |

Токен для CLI выдаёт `claude setup-token` — на сервере интерактивно
залогиниться нечем, поэтому он лежит в секретах репозитория и передаётся
контейнеру переменной окружения. Путь к CLI задаёт сам образ
(`CLAUDE_CLI_PATH=/usr/local/bin/claude`), из деплоя эта переменная убрана:
пустой секрет затирал бы её через `-e` и молча выключал ступень.

**У прокси GigaChat отключена проверка TLS-сертификата**
(`--gigachat.verify-ssl-certs false`): API Сбера подписан российским УЦ, и в
контейнер его корневой сертификат завести не удалось — ни через
`update-ca-certificates`, ни через `--gigachat.ca-bundle-file`. Решение
осознанное, по указанию Павла.

На корпоративном scope **нет модели `GigaChat-3-Ultra`** из первоначального
плана — старшая доступная `GigaChat-2-Max`, зрение у неё работает.

## Нетривиальные детали

- **Матчинг ответов идёт через `reply_to_message`**, а не «последнее сообщение
  в чате»: иначе две параллельные капчи перепутали бы ответы. `ForceReply`
  открывает поле ответа сразу, чтобы не выбирать «ответить» вручную.
- **Задачи в SQLite, а не в памяти** — рестарт службы не должен терять
  незакрытый запрос: клиент на другом конце всё ещё ждёт.
- **Telegram polling живёт в одном экземпляре.** У Bot API либо polling, либо
  webhook: второй потребитель отбирал бы обновления у первого.
- **Промпт у моделей общий** (`solvers/prompt.ts`) — иначе сравнение точности
  GigaChat и Claude в `/api/stats` было бы бессмысленным.
- **Каждая попытка пишется в `attempts`** с исходом и длительностью. По этой
  таблице видно, стоит ли ступень своих денег.
- **Ошибка ступени не роняет каскад** — переходим к следующей.
- **Ответ человека нормализуется от кириллических двойников**: с русской
  раскладки получается «ХК7Р9» вместо «XK7P9», на вид не отличить, а сайт такой
  ответ отбивает. Правим только когда подсказка говорит про латиницу — иначе
  испортили бы честно кириллическую капчу.
- **Реакции вместо сообщений о статусе**: 👀 забрали ответ, 👍 подошёл,
  👎 сайт отклонил. Telegram принимает эмодзи только из своего набора, поэтому
  галочки и крестика здесь нет.
- **Ступень Claude ходит через `claude` CLI, а не по API** — ключ держать не
  нужно. Промпт передаётся через stdin: аргументом его съедает вариадический
  `--add-dir`, и CLI жалуется, что промпта нет.

## Проверено

Тестами (16 шт.): каскад останавливается на первом ответе, падение ступени не
роняет прогон, `reject` идёт на следующую ступень и не переспрашивает
провалившуюся, исчерпанный каскад даёт `failed`, каждая попытка попадает в
аудит, задача переживает рестарт, кириллические двойники правятся только при
подсказке про латиницу.

Вживую на тестовой капче `XK7P9`:

- локально — все три ступени прочитали её верно, включая `claude` через CLI;
- на сервере — `gigachat` и `human` прочитали верно через
  `https://captcha.paulislava.space/api`;
- реакции: 👀 на взятый ответ, 👍 на подошедший, 👎 после `reject`.
