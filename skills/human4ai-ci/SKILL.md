# Фоновое ожидание CI

## Интеграции

Обязательны Node.js 18+ и CLI нужного сервиса: `glab` для GitLab, `gh` для
GitHub. CLI должен быть авторизован на хосте из переданного URL, включая
собственные инстансы GitLab и GitHub Enterprise. Сначала проверь доступ
безопасным чтением через соответствующий CLI; настройку предлагай только
при отсутствии доступа. Токены не читать и не печатать.

Для проверки сохранённого результата внешние интеграции не нужны.
`alice-say` нужен только для отдельно согласованного голосового уведомления.
Колонку выбирай по актуальному списку `alice-say --devices-online`; при
нескольких совпадениях не угадывай устройство.

## Запуск

На Mac доступны общие команды:

```bash
human4ai-ci-track start --url 'https://git.example.org/group/project/-/pipelines/123' --cwd '/path/to/repository'
human4ai-ci-track start --url 'https://github.example.org/owner/repo/actions/runs/456' --job-name 'deploy' --cwd '/path/to/repository'
```

Можно передать URL конкретной job. `--job-name` задаёт точное имя job внутри
указанного pipeline/run; GitLab downstream учитываются. Возвращённый `id`
используй для дальнейших запросов. Фоновый процесс переживает выход
запустившей команды.

В автономной копии плагина вместо обёрток используй
`node <каталог-плагина>/scripts/ci-track.cjs` и
`node <каталог-плагина>/scripts/ci-status.cjs`. В репозитории human4ai
есть такие же точки входа в `scripts/`.

## Дождаться результата

```bash
human4ai-ci-status '<id>' --wait-ms 300000
```

Это длительное ожидание локального результата, а не новый опрос GitLab/GitHub.
Запускай тул с максимальным доступным временем ожидания; если он допускает
ожидание без лимита, используй `--infinite`. Не выбирай короткий таймаут для
быстрой проверки. Для Codex `exec_command` допускает начальный yield до
30000 мс; если процесс ещё работает, продолжай ту же сессию через
`write_stdin` с `yield_time_ms: 300000`. При асинхронном вызове сохраняй
возможность отвечать пользователю между ожиданиями.

Если команда вернула JSON `status: "in_progress"`, повторяй ту же команду
с максимальным ожиданием, пока не придёт терминальный результат. Только
`in_progress` требует повторения: `success`, ошибка, отмена, блокировка,
прерывание и итоговый таймаут завершают цикл. Не переходи к ручному опросу
каждой job. Таймаут одного вызова статуса не означает таймаут самого CI.

## Остановка и продолжение

```bash
human4ai-ci-track cancel '<id>'
```

Отслеживание завершается, если условие выполнено либо стало недостижимым:
CI отменён, заблокирован обязательным действием, завершился ошибкой, нужная
job пропущена или отсутствует в завершённом pipeline/run. При смерти
фонового процесса статус возвращает прерывание, а не бесконечный
`in_progress`. Сохраняй точный итог и причину. Не выдавай завершение
отслеживания за успешный деплой.

`--on-success '["команда","аргумент"]'` разрешён только для заранее
авторизованного следующего действия. Передавай массив аргументов JSON,
не shell-код. Продолжение выполняется один раз после подтверждённого успеха;
при ошибке продолжения результат не должен становиться успешным.
Слияние MR, деплой или сообщение людям не разрешаются самим фактом
использования этого навыка.
